# 부산한입(BusanBite) MVP — 디자인·기능 이관 명세서

이 문서는 완성된 데모(`busanbite-demo.html`)를 실제 프로젝트 코드베이스로 이식하기 위한 명세서다.
CLI 코딩 에이전트(Claude Code 등)에게 이 문서 전체를 프롬프트로 붙여넣고, `busanbite-demo.html`을
레퍼런스 구현으로 함께 첨부해서 넘기면 된다. 애매한 값(정확한 색상 hex, 애니메이션 타이밍, 카피 문구 등)은
전부 이 HTML 안에 이미 구현되어 있으니, 이 문서와 HTML이 다르면 **HTML을 정답으로 따를 것.**

---

## 0. 에이전트에게 주는 작업 지시

> 아래 명세와 첨부된 `busanbite-demo.html`을 참고해서, 이 저장소의 기존 스택(프레임워크·라우팅·스타일링 방식)에
> 맞게 부산한입 MVP의 디자인과 기능을 동일하게 이식해줘. 작업 시작 전에 이 저장소가 어떤 프레임워크를 쓰는지
> 먼저 확인하고, 그 구조에 맞는 컴포넌트/파일 단위로 나눠서 구현해줘. 픽셀 단위 색상·타이포그래피·인터랙션
> 로직은 HTML 레퍼런스를 그대로 따르고, 임의로 디자인을 바꾸지 마.

## 1. 프로젝트 개요

- **이름**: 부산한입 (BusanBite)
- **한 줄 설명**: 외국인 관광객이 한글 메뉴판을 찍으면 AI가 설명해주고, 원하는 주문/요청을 현지어→한국어 카드로 바꿔 보여주는 여행 도우미 앱
- **이번 MVP 범위**: "먹기"(메뉴 스캔→분석→주문카드), "말하기"(음성 인식 시뮬레이션→전달카드), AI 챗봇 오버레이
- **현재 상태**: 정적 데모(하드코딩된 샘플 데이터 + 시뮬레이션). 실제 서비스 전환 시 연동이 필요한 지점은 9번 항목에 표시.

## 2. 디자인 시스템

### 2.1 컬러 팔레트 — 부산광역시 공식 상징마크 4색만 사용

| 이름 | 역할 | HEX |
|---|---|---|
| Busan Dynamic Magenta | 주 강조색(CTA, 브랜드 타이틀, 활성 상태) | `#EC008C` |
| Busan Original Blue | 그라데이션 딥톤(주문카드 배경 하단) | `#003795` |
| Busan Open Violet | 보조 강조색(마이크 버튼, 옵션 on 상태, 말하기 카드 하단) | `#58228F` |
| Busan Global Light Blue | 보조 강조색(번역명 텍스트, 말하기 카드 상단, 배경 글로우) | `#0095D9` |

중립색(브랜드색 아님, UI 배경/텍스트용):
- 배경(스테이지): `#0d0a1f` → `#140d2e` 그라데이션 (다크모드 `#08051a`→`#0d0a1f`)
- 카드/종이 배경: `#fbf8ff`, 보조 배경 `#f1eafb`
- 잉크(텍스트/버튼): `#1a1030`
- 보더/헤어라인: `#e4d9f5`, 뮤트 텍스트: `#8b7fa0`

**핵심 규칙**: 주문카드(고객용/사장님용 공통) 배경은 항상 `linear-gradient(155deg, 마젠타 0% → 블루 100%)` —
실제 부산 상징마크 B 심벌의 마젠타→블루 대각선 그라데이션을 그대로 재현한 것. 말하기(전달) 카드는
`linear-gradient(155deg, 라이트블루 0% → 바이올렛 100%)`로 구분해서, 두 카드 타입이 색으로 구분되게 한다.

### 2.2 타이포그래피
- 헤드라인/브랜드/메뉴명/카드 타이틀: **Song Myung** (Google Fonts, 붓글씨 느낌의 한글 세리프) — 시장 간판 정서
- 본문/UI 전체: **Noto Sans KR** (400/500/600/700/900)
- 두 폰트만 사용, 그 외 폰트 추가 금지

### 2.3 레이아웃 개념
- 휴대폰 목업 프레임(폭 380px, 높이 720px, 라운드 46px, 노치 포함)을 화면 정중앙에 배치하는 "라이브 데모" 형태
- 프레임 바깥 배경은 어두운 무대(스테이지) + 마젠타/라이트블루 은은한 radial-gradient 글로우 2개
- 프레임 안은 화면 전환형 SPA 구조: `.screen.active` 클래스로 스와이프 전환(opacity+translateX, 0.4s ease)
- 상단에 모드 탭(먹기/말하기), 진행 단계 점(stepper dot) 표시

### 2.4 공통 컴포넌트 규칙
- 버튼(필/캡슐형): `border-radius:100px`
- 카드: `border-radius:16~22px`
- 칩(태그/옵션/통화/언어): 얇은 보더 + 흰 배경, `.active`/`.on` 상태는 배경 반전(잉크 배경 + 브랜드색 텍스트, 또는 옅은 브랜드색 배경)
- 그림자는 절제해서 사용 (주요 CTA와 카드에만, `rgba(0,0,0,0.4~0.5)` 또는 브랜드색 기반)
- 애니메이션은 "한 번의 연출"만: 카드 리스트 등장 시 순차 fade-up(stagger), 셔터 촬영 시 플래시, 카드 플립 시 180° 회전 — 그 외 hover 남발 금지

## 3. 화면 구조 & 내비게이션

```
[모드탭: 먹기 | 말하기]  (전역, 항상 노출)
[스텝 점 표시]           (모드별로 총 개수 다름: 먹기=3, 말하기=2)

먹기 모드
  1) 촬영 화면 (screen-scan)
       → 셔터 누르면 → 2) 분석 결과 화면 (screen-result)
                            → "주문카드 만들기" 누르면 → 3) 주문카드 화면 (screen-card)

말하기 모드
  1) 마이크 홈 (screen-talk-home)
       → 마이크/프리셋 문구 탭 → 2) 전달 카드 화면 (screen-talk-card)

[AI 챗봇 플로팅 버튼 + 패널]  (전역, 모드 무관하게 항상 오른쪽 아래 노출)
```

---

## 4. 화면별 상세 스펙

### 4.1 촬영 화면 (스캔)
- 카메라 뷰파인더 프레임(모서리 4개 브라켓 장식) 안에 샘플 메뉴판(SVG, "자갈치 국밥집" 메뉴 4개 + 가격) 표시
- 하단 셔터 버튼(원형, 잉크 보더 + 흰 배경 + 안쪽 원은 바이올렛)
- 셔터 클릭 시: 흰 플래시 페이드(0.5s) → 260ms 후 분석 결과 화면으로 전환

### 4.2 분석 결과 화면
- 상단: 언어 선택 칩 행 (**English를 맨 왼쪽**, 그다음 **한국어(기본 선택)**, 繁體中文, 简体中文, 日本語)
- 그 아래: 통화 선택 칩 행 (₩원화 기본, NT$대만달러, ¥엔화, CN¥위안화, $달러) — 환율은 데모용 고정값
- 그 아래: "🫘 콩 알레르기 있어요 — 전달하기" 토글 칩, **기본값 ON** (안 눌러도 주문카드에 알레르기 문구가 들어가야 함)
- 메뉴 카드 리스트(스크롤 영역), 각 카드 구성:
  - 한글 메뉴명(항상 고정 표시) + 선택 언어 번역명(한국어 선택 시엔 번역 줄 숨김) + 가격(선택 통화로 환산 + 원화 병기)
  - 맵기 아이콘(고추 1~3개, 해당 레벨까지 활성)
  - 태그(원재료 등, 언어별 번역)
  - **알레르기 그리드는 토글 없이 항상 바로 노출** — 8개 알레르기 아이콘(돼지고기/갑각류/밀/우유/땅콩/대두/계란/메밀)을 4열 그리드로, 해당되는 것만 강조(바이올렛 배경+보더), 나머지는 옅게
  - "먹는 법" 라벨(언어별) + 설명 텍스트(언어별)
  - 하단: 옵션 칩(메뉴별로 다름, 복수 선택 가능한 구조로 설계) + 수량 스테퍼(−/개수/+)
    - 돼지국밥, 순대국밥 → "밥 적게" 옵션
    - 물밀면 → "덜 맵게" 옵션
- 하단 고정바: "선택 N개"(언어별 문구) + "주문카드 만들기" 버튼(선택 0개면 비활성)

### 4.3 주문카드 화면 — **가장 중요한 인터랙션**
- 카드 상단: "TO. 사장님" 형태의 kicker + "사장님, 주문할게요!" 형태의 타이틀
- 카드 본문: 선택한 메뉴명 + 수량 (`order-line`, 큰 글씨 — 폰트 21px, 굵게)
- 카드 하단: 선택된 옵션/알레르기 문구를 알약(pill) 형태로 각각 한 줄씩 표시
- **언어 전환 로직 (핵심)**:
  - 카드가 처음 만들어질 때(플립 전) = **고객이 선택한 언어**로 kicker/타이틀/메뉴명/옵션 문구가 전부 표시됨 (자기가 뭘 주문하는지 확인하는 용도)
  - 화면 하단 "사장님께 보여드리기" 버튼도 **고객 언어로 표시**됨 (예: 중국어 선택 시 "拿給老闆看 ↻")
  - 이 버튼을 누르면: 카드가 **180도 회전(flip)** + 동시에 카드 안의 모든 텍스트가 **한국어로 전환**됨 (kicker="TO. 사장님", 타이틀="사장님, 주문할게요!", 메뉴명=한글명, 옵션 문구=한국어 원문)
  - 버튼 라벨 자체는 계속 고객 언어를 유지("다시 내 화면으로"에 해당하는 각 언어 문구) — 카드 "내용물"만 언어가 바뀌고, 버튼 UI는 고객이 계속 읽을 수 있어야 하므로 그대로 둠
  - 다시 누르면 원상복구(고객 언어 + 원래 회전 방향)
  - 이 흐름은 "고객이 확인 → 뒤집어서 사장님께 보여줌"이라는 실제 사용 동작을 그대로 재현한 것이므로 절대 생략하면 안 됨
- 화면 상단 라벨, 뒤로가기("메뉴 수정") 버튼, 카드 아래 안내 문구("버튼을 누르면 카드가 180° 돌아가요…")도 전부 언어별로 표시
- "처음부터 다시 데모하기" 링크는 상태 초기화 후 촬영 화면으로 복귀

### 4.4 말하기 모드
- 마이크 버튼(원형, 바이올렛) — 클릭 시 pulse 애니메이션 0.9s → 900ms 후 인식 완료
- 마이크는 내부적으로 프리셋 문구 4개를 순환하며 "인식"하는 시뮬레이션 (실제 STT 아님)
- 프리셋 문구 칩 4개(카드 결제 되나요? / 이거 얼마예요? / 포장 가능해요? / 화장실이 어디예요?)를 직접 탭해도 동일하게 동작 — 라이브 데모에서 마이크가 실패할 리스크를 없애기 위한 안전장치
- 인식 완료 후 전달 카드 화면으로 전환: 인식된 원문(영어) + 한국어 번역이 큰 글씨로 표시되는 카드(라이트블루→바이올렛 그라데이션), "상대방에게 보여드리기" 버튼으로 180도 플립

### 4.5 AI 챗봇 (전역 오버레이)
- 우하단 플로팅 버튼(잉크 배경 + 마젠타 아이콘) → 클릭 시 패널이 아래에서 위로 슬라이드업(0.35s)
- 추천 질문 칩 4개(매운 정도/환전/채식/화장실) 탭 → 유저 말풍선 + "AI가 입력 중…" → 650ms 후 AI 답변 말풍선
- 직접 텍스트 입력도 가능, 키워드 매칭(맵/환전/채식/화장실/카드결제)으로 캔드 답변, 매칭 없으면 안내 fallback 문구
- **주의**: 이 챗봇은 실시간 LLM이 아니라 하드코딩된 키워드 매칭 데모임을 인지하고 이식할 것 (실제 서비스 전환 시 연동 필요)

## 5. 데이터 모델 (레퍼런스: HTML `<script>` 내부)

```js
// 메뉴 아이템 구조
{
  id, ko(한글명), priceKRW, spice(0~3), options: ['lessSpicy' | 'lessRice'],
  allergens: { pork, shrimp, wheat, milk, peanut, soy, egg, buckwheat } (boolean map),
  i18n: {
    ko: { name, tags:[], howto },
    en: { name, tags:[], howto },
    'zh-Hant': { name, tags:[], howto },
    'zh-Hans': { name, tags:[], howto },
    ja: { name, tags:[], howto },
  }
}

// 옵션 정의 (덜 맵게 / 밥 적게 / 콩 알레르기)
OPTION_DEFS[key] = {
  icon, noteKo(한국어 요청 문구),
  i18n: { [lang]: { label, note } }  // ko는 label만 있음(카드에서 이미 한국어라 note 별도 불필요)
}

// 화면 UI 문구 전체 (스캔/결과/카드 화면의 모든 라벨·버튼·힌트)
UI[lang] = {
  scanLabel, scanHint, resultLabel, backToScan, analyzing,
  selected(n) => string, makeCard, cardLabel, backToResult,
  cardKicker, cardTitle, flipShow, flipHide, flipHint, restart
}

// 통화 환율 (데모용 고정값)
RATES = { KRW, TWD, JPY, CNY, USD } // symbol, rate(KRW 기준 환산), decimals

// 알레르기 8종 공통 정의 + 언어별 라벨
ALLERGENS = [{key, icon}, ...]
ALLERGEN_LABELS[lang] = { pork, shrimp, wheat, milk, peanut, soy, egg, buckwheat }
```

지원 언어 코드: `ko`, `en`, `zh-Hant`(번체), `zh-Hans`(간체), `ja`. 언어 추가 시 위 모든 딕셔너리에
동일한 키로 번역을 추가해야 빠짐없이 반영됨.

## 6. 핵심 인터랙션 로직 요약 (그대로 이식)

1. **언어 칩 변경** → 메뉴 카드 리스트 재렌더링 + 모든 화면 UI 문구(`UI[lang]`) 갱신 + (주문카드 화면이 열려 있고 아직 플립 안 된 상태라면) 카드 내용도 즉시 갱신
2. **통화 칩 변경** → 가격 표시만 재계산, 언어와 무관
3. **알레르기 그리드** → 토글 없이 always-visible
4. **옵션 토글(덜 맵게/밥 적게)** → 아이템별 state, 다중 선택 가능한 구조로 설계(현재는 아이템당 1개 옵션만 존재)
5. **콩 알레르기 토글** → 전역 state, 기본값 true
6. **주문카드 생성** → 그 시점의 선택 내역(메뉴+수량+활성 옵션+콩 알레르기)을 스냅샷으로 고정한 뒤, "고객뷰"로 렌더링
7. **카드 플립** → 고객뷰 ↔ 사장님뷰(한국어 고정) 텍스트 스왑 + 180도 회전, 플립 버튼 라벨은 항상 고객 언어 유지
8. **말하기 프리셋/마이크** → 동일한 플립 메커니즘 재사용(색상만 다름)

## 7. 반응형·접근성 참고
- 모바일 우선(휴대폰 프레임 자체가 390px 이하에서 92vw로 축소)
- 다크모드 대응: `prefers-color-scheme: dark` 및 `data-theme` 속성 지원 (스테이지 배경만 약간 더 어둡게)
- 모든 인터랙티브 요소는 버튼/링크 시맨틱 유지, 포커스 아웃라인 제거하지 말 것

## 8. 레퍼런스 구현
첨부된 `busanbite-demo.html`이 위 명세의 완전한 동작 구현체다(HTML+CSS+JS 단일 파일, 외부 의존성은
Google Fonts뿐). 색상 hex, 애니메이션 duration/easing, 문구 원문(다국어 번역 포함), 컴포넌트 마크업 구조는
전부 이 파일에서 그대로 가져와 포팅할 것. 새로 디자인하거나 임의로 변형하지 말 것.

## 9. 실제 서비스 전환 시 연동 필요 지점 (현재는 전부 목업/시뮬레이션)
